## Progressive architecture decision
`PROPOSED → implemented only after route generation verification`

Use the existing TanStack Router file-route hierarchy with `/admin` as the authorized shell parent and child workspace routes. To minimize churn while preserving existing business logic, the first extraction keeps the verified `PlatformAdminPage` presentation/data implementation reusable and moves route selection from local-only tab state to real child URLs. Full component decomposition beyond this route boundary is intentionally deferred unless required by a verified W7.9 defect.

A dynamic child route may be used only as a routing adapter for the verified workspace names; it must whitelist the actual route keys and redirect unknown workspaces safely to `/admin`. It must not expose unavailable capabilities.

## Legacy compatibility
`PROPOSED`
- Known `/admin?tab=<value>` values normalize to their verified child route.
- `overview` normalizes to `/admin`.
- Unrelated query parameters are preserved where the router contract permits.
- Unknown legacy tab values fall back safely to `/admin` without a loop.
- Authorization remains enforced by the existing Admin page/data contracts after navigation.

## Deferred / unavailable routes
`VERIFIED`
- No `/admin/restaurants/:id` detail route exists or is justified by current source.
- No `/admin/clients/:id` detail route exists or is justified by current source.
- No Security, Platform Health, or Configuration route exists because W7.8 confirmed no independent real capability for them.
- `/admin/onboarding` remains an existing specialized route and is outside the workspace mapping above.

## State preservation
Each migrated workspace must preserve its existing loading, empty, error, permission-denied/unavailable, populated, action, RTL, responsive, and accessibility behavior. Route splitting must not fabricate or alter data.

## Key risks
- `src/routeTree.gen.ts` must be regenerated and committed exactly.
- Parent/child route nesting must not hide existing `/admin/onboarding`.
- Legacy query normalization must not bypass authorization or create redirect loops.
- Navigation must become route-based without leaving a second competing local-tab navigation model.
- Direct child URLs must not render stale unauthorized Admin content.
