# W7.9 Platform Admin Route Architecture

## Status
`VERIFIED / FINAL` — 2026-09-15.

## Purpose
Progressively move Platform Admin from the monolithic local-tab experience to real TanStack Router URLs without rewriting Admin business logic or changing security boundaries.

## Final route structure
- `/admin` — Overview / authorized Admin shell
- `/admin/restaurants` — tenants workspace
- `/admin/clients` — clients workspace
- `/admin/branches` — branches workspace
- `/admin/orders` — orders workspace
- `/admin/subscriptions` — subscriptions workspace
- `/admin/service-requests` — requests workspace
- `/admin/leads` — leads workspace
- `/admin/projects` — projects workspace
- `/admin/analytics` — analytics workspace
- `/admin/activity` — activity workspace
- `/admin/system` — combined system/security workspace

`/admin/onboarding` remains an existing specialized route outside the workspace adapter.

## Implementation
- `src/routes/admin.tsx` remains the authorized parent route and Overview.
- `src/routes/admin/$workspace.tsx` is the protected routing adapter.
- `ADMIN_ROUTES` is the single tab-to-route mapping used by navigation and legacy normalization.
- `ADMIN_WORKSPACE_TABS` is the verified workspace-to-tab mapping used by the child route.
- `PlatformAdminPage` remains the existing data/action/presentation implementation; the child route passes `initialTab` and does not duplicate business logic.
- `src/routeTree.gen.ts` is generated by the existing route-generation process and was verified fresh in CI.

## State and URL compatibility
Existing Admin interaction still executes `setTab(next)` before URL synchronization. The URL navigation is additive through `navigate({ to: ADMIN_ROUTES[next] })`. This preserves the existing Admin state contract while making the URL the durable navigation location for bookmarks, refresh, and browser history.

Legacy `/admin?tab=<value>` handling occurs in the parent route `beforeLoad`. Known values map to the verified workspace route, `tab` is removed, unrelated query parameters are retained through the router search object, and unknown values safely normalize to `/admin` with `replace: true`.

## Authorization
The existing parent Admin authorization and data-layer authorization remain the security boundary. The child route only validates the workspace key and redirects unsupported keys. It does not infer or grant role, tenant, branch, entitlement, or privilege and cannot bypass `requirePlatformAdmin` / `assertPlatformAdmin`.

CI browser QA uses an isolated temporary PostgreSQL service, compatible existing migrations, Supabase-compatible roles, and `dev-user` seeded into `menu_v3.platform_admins`. The fixture exists only in the runner and is not a production migration.

## Intentionally deferred
- `/admin/restaurants/:id` and `/admin/clients/:id` detail routes.
- Independent Security, Platform Health, or Configuration routes because no separate verified capabilities exist.
- Full decomposition of `PlatformAdminPage` into smaller business modules.
- W7.10 full-product mobile/responsive pass.
- W7.11 final visual QA.

## Data integrity
No new data source, metric, chart, recommendation, health score, security event, activity record, operator sample, or fabricated platform state was introduced. Existing loading, error, empty, denied, unavailable, populated, and action behavior is reused.
